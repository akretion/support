This module receives the releases pushed by a customer project (see
``support_release``), creates a release per version, links the tickets
it ships and moves them to the stage matching the deployment
environment.

The core is a single POST route added to the existing ``cross_connect``
endpoint, authenticated by the same ``api-key`` as the support feature.
There is no git logic here: the ticket ids are given by the payload, and
the partner of the release is the one of the projects of the tickets.

Usage
=====

Two stages are configured once for all the projects, in *Settings >
Support Releases*:

- the preprod stage, applied when a release is received from preprod;
- the prod stage, applied when a release is received from prod.

A ticket is never moved backwards: the stage is only written when the
target stage is further than the current one, comparing their sequences.

Once a release has a production deployment date, a payload coming from
preprod for the same version is ignored, so a preprod redeployment
cannot reopen tickets that are already closed.

The ``next`` release of a client is absorbed by the first numbered
version received for that client, then removed.
