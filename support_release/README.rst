This module records the releases deployed on a customer project and
pushes them to the Akretion support server, where the tickets shipped by
each release are linked and moved to the stage matching the deployment
environment.

The information comes from a migration generated in the project by the
release script, so the module never reads git: it only stores what the
migration hands it and relays it.

A release is identified by its version. When no version is defined yet,
the version is ``next``, and the first numbered version absorbs it.

Usage
=====

The release information is registered by a migration generated in the
project (usually ``custom_all``) at each deployment:

.. code:: python

   from openupgradelib import openupgrade


   @openupgrade.migrate(use_env=True)
   def migrate(env, version):
       if "support.release" not in env:
           return
       env["support.release"]._register_deployment(
           version="next",  # or the numbered version, e.g. "14.0.2610.26.0"
           tickets=[25882, 25890],
       )

The guard on the model presence keeps a database where this module is
not installed from failing its module update.

Releases are then pushed by the cron *Support Release: push pending
releases* (every 10 minutes, one release per run, oldest first).

Every deployment sends the complete list of tickets of the release, so
registering the same version again replaces its tickets instead of
completing them. A call with a version or a ticket list that cannot be
used raises: a broken generated migration must be visible in the log,
not silently ignored.

A release is only marked as sent once the support server accepted it, so
a failed push is retried by the next run.

The push only happens when ``running_env`` is ``preprod`` or ``prod``:
it is set by ``server_environment`` from the ``RUNNING_ENV`` environment
variable, so there is nothing else to configure in the module.

The generated migration must exist on the **main branch only**: the CI
sets ``RUNNING_ENV=preprod`` on every container, so a review environment
carrying a migration would announce a version that was never deployed.

Bug Tracker
===========

Bugs are tracked on `GitHub Issues <https://github.com/Akretion/support/issues>`_.
In case of trouble, please check there if your issue has already been reported.
If you spotted it first, help us to smash it by providing a detailed and welcomed
`feedback <https://github.com/Akretion/support/issues/new?body=module:%20support_release%0Aversion:%2018.0%0A%0A**Steps%20to%20reproduce**%0A-%20...%0A%0A**Current%20behavior**%0A%0A**Expected%20behavior**>`_.

Do not contact contributors directly about support or help with technical issues.
